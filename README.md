# 刷题 · PDF 题库自动解析 + 仿粉笔答题系统

把一份 PDF 试卷（粉笔导出的那种）丢进来，本地大模型自动切题、标注分类、给出答案与解析，
然后在一个**仿粉笔练习页**的界面里刷题、判分、看解析。

全部在本地跑：模型走本机的 OpenAI 兼容代理（默认 `http://127.0.0.1:3050/v1`），
题库和图片落在 `data/` 下，不上传任何东西。

---

## 一、它长什么样

- **导航**：顶栏「做题历史 / 错题本 / 设置」三个同级入口；
  页面内用「按试卷刷 / 按题型刷」两个 tab 切换刷题方式
- **试卷页（首页）**：概览（几套卷 / 多少题 / 已刷题数 / 累计正确率 / 待复习错题）、
  按试卷名搜索、按导入时间/题量/错题数排序；每套卷带年份角标、题量、答案是否齐全、
  已刷多少、错题数、上次得分
- **做题历史**：每次交卷都留一条记录（整卷 / 冲刺 / 中止、得分、对错、用时）；
  点「复盘」直接还原那一次的作答并判分看解析，也可以删掉某条记录- **答题页**：仿粉笔的题目卡流（题号 + 单/多选题标签 + 选项圆标 + 标记/笔记），
  顶部计时（可暂停）、**换卷下拉**、**冲刺模式**、**重置**、**中止**、
  设置、下载、交卷，左下角浮着答题卡
- **按题型刷题**（仿牛客专项练习）：9 个题型，每类显示「已刷 X/总数」进度条；
  点进去选题量（10/20/30/50 或**自定义 1~200**）、**每题限时**（不限时 / 30/45/60/90 秒或自定义），
  **优先抽没刷过的题**，刷完了自动从头循环；逐题作答 + 提交看解析，结束给正确率和错题清单
- **题型练习也支持那套做题功能**：总用时计时（可暂停）、限时冲刺（超时自动判错并跳下一题）、
  重置（清空本次作答、计时归零）、中止（已答的记进度 + 保存现场，
  下次在题型页点「继续练习」从第 N 题接着做）
- **刷题进度**：每道题刷过就记一笔（来源分整卷、冲刺、按题型），跨模式共享；
  题型页可「重置进度」把它清零——**只清进度，错题本和题目都不动**
- **中止 / 继续**：中途可以「中止」，只提交已作答的题（留空的不判分、也不进错题本），
  进度存在服务端；首页该卷会显示「中断于 2/80 题」和「继续做题」，点进去作答与计时都接着上次
- **冲刺模式**（练速度）：一题一屏，**每题限时可选 30/45/60/90 秒或自定义**，
  选完立刻进下一题、**不能回头改**；时间到自动跳过；键盘 `A-D` / `1-4` 直接作答；
  结束给正确率、平均用时和错题清单。题量同样可选 10/20/40/全部或自定义
- **重置答题**：做题页一键清空所有作答并把计时归零（标记和笔记保留）；
  交卷后另有「重新开始」，会连标记笔记一起清掉
- **练习范围**：全部 / 未做 / 错题 / 标记，一键切换只看想练的部分
- **答题卡**：按分类分组的题号格子，已答/未答/标记一目了然，点号跳转
- **交卷后**：得分条、正确率分布条、"只看得错的题"，每道题展开正确答案 / 你的答案 /
  答案来源 / 解析，并可**手动修订答案**、**按需生成解析**、**重新解析**、**清空重做**
- **错题本**：交卷时答错的题自动入库；可看全部/按试卷筛选、标记已掌握、移除；
  「开始重刷」进入即时判分模式（点选项立刻出对错），对着答案复习
- **多选题**：个别题答案是 `AD` 这类多选，选项可多选、判分按集合比较
- **图片题 / 论述题**：有些题（联想、性格测评那类）把题干和四个选项整张截成图片，
  文本层只剩 `A.选项A` 占位。这类题标成「图片题」，只展示截图 + 官方解析，不参与判分；
  论述题（无 ABCD、答案是文字）单独显示参考答案框
- **答案可溯源**：模型自答的标"模型推理 + 置信度"；从粉笔解析页导入的标"粉笔标准答案"
- **题目编辑**：题干 / 选项 / 答案 / 考点 / 解析都能改（`Ctrl+S` 保存），
  右边并排显示**这道题所在的原卷页面**，可翻页跳页、另开 PDF 对照；
  动作区记「手工修订」时间，改错的答案还能一键回滚成官方值
- **进度不丢**：作答、标记、笔记、计时都存在浏览器本地，刷新继续；成绩与错题存服务端

## 二、快速开始

### 1. 环境

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 20（推荐 22/24） | 后端与前端 |
| Python | ≥ 3.9 | 只用于 PDF 几何切题与图片裁剪 |
| PyMuPDF | 最新 | `pip install pymupdf` |

```powershell
pip install pymupdf
npm install
```

### 2. 配置模型

复制 `.env.example` 为 `.env`（或直接在网页「设置」里改）：

```ini
LLM_BASE_URL=http://127.0.0.1:3050/v1
LLM_MODEL=deepseek/deepseek-v4.1-flash
LLM_VISION_MODEL=deepseek/deepseek-v4-flash-vision-exp
LLM_API_KEY=            # 留空则自动读本机 CommandCodeGo 代理数据库
```

- `LLM_API_KEY` 留空时，会尝试只读读取本机 `CommandCodeGo-manager/data/ccp.db`
  里的上游密钥；也可以在网页「设置」里手填（只显示掩码，不回显明文）。
- 任何 OpenAI 兼容服务都能接：把 `LLM_BASE_URL` 换成 `https://api.openai.com/v1` 这类地址即可。

### 3. 导入题库

两条路，效果一样：

```powershell
# A. 命令行
npm run parse -- "D:\Download\2025中国移动校园秋招试卷（网友回忆版）.pdf"

# B. 网页：npm start 之后，把 PDF 拖进首页的虚框
```

衍生命令（题库已经在 `data/` 里时用）：

```powershell
npm run repair        # 把没拿到答案的题单独重跑一遍
npm run reclassify    # 全卷重新做一次一致的题型划分
```

### 4. 开刷

```powershell
npm start          # → http://127.0.0.1:7788
```

答题页支持深链接直达某一题：`#/exam/<题库id>/<题号>`。

## 三、解析是怎么做的

单纯"把 PDF 文本丢给模型"是不够的：粉笔导出的 PDF 里，
**题号是独立文本块、选项有单双列两种排布、图形题的图和选项全是图片、一题还会跨页**。
所以整条流水线分成两步——几何负责切准，模型负责读懂。

```
PDF ──PyMuPDF──▶ 坐标切题 ──▶ 结构化题目 ──┬─▶ 文本题：批量交模型标注答案/解析/分类
                                          └─▶ 图形题：裁剪配图 → 视觉模型判读
                                                    │
                                                    ▼
                                          data/exams/<id>/exam.json
```

### 1. 坐标切题（`tools/pdf_extract.py`）

按粉笔版式做的几条规则：

- **题号定位**：题号 `N.` 是独立文本 run，靠左栏且 `y` 与题干首行一致。
  左右边距**随导出版式变化**（原始卷约 x=29~42，解析版约 x=59~67），所以不写死阈值：
  先取所有"形如 `N.` 的短行"右边界的中位数当栏位，再按它筛选。
  按 `(页码, y, x)` 排序后，题号自然排在题干首行之前，"题号 = 题目起点"就可靠了。
- **选项切分**：`A./B./C./D.` 打头的行归入选项；双列排布（`B/D` 的 `x ≈ 297`）
  按 `x` 判断列归属；选项换行的续行按列回填。
- **跨页**：一题的跨度从本题题号到**下一题题号**，所以"题号在页尾、选项在次页顶部"
  照样能拼对。
- **标准答案**：解析版 PDF 里每题后面有 `正确答案： X`，按"归属于它前面最近的题号"
  抽出来；多选会写成 `正确答案： A D`，按字母组归一成 `AD`。
- **图片归属**：分两步——先认**紧贴选项标签行上方**的那张图（它是本题的选项图，
  通常排在题号之前，按题号前缀会算错题），其余图按"图片中心落在哪个题号之后"归属
  （题干图常常微微越出题号行，用上沿会算给上一题）。按 role 分别裁剪渲染成 PNG。
  行内小图（如分数）在题干里留 `〔图〕` 标记。
- **噪音过滤**：页眉标题条、页脚"本试卷由粉笔用户…生成 / 第 N 页，共 M 页"、
  整幅包装图、以及没有任何题目锚点的装饰页（卷尾 logo 之类）全部剔除。

### 2. 模型标注（`server/lib/pipeline.mjs`）

- **文本题**：按 4 题一批、并发 3 个请求，要求模型返回严格 JSON 数组
  （`no / section / answer / explanation / confidence`）。
  答案会按选项字母白名单校验，非法的丢弃而不是照抄。
  某一批失败就**二分重试**直到单题，单题仍失败才记下原因，不会让整份卷子丢答案。
- **图形题**：把裁剪后的图按 base64 交给视觉模型，强制 `confidence=low`，
  界面上也明确标成"视觉模型 / 低置信"，提醒人工复核。
  空间重构题要在"脑子里转立方体"，思考特别长，所以这一路把 `max_tokens` 放宽到
  32768——额度给小了会出现"想了 1.5 万字却一句话没说"的空回复。
- **统一分类**：分批标注时每批看不到别的题，分类容易各说各话。
  所以最后再用一次全卷请求，让模型直接给**分节区间** `[{section, from, to}]`，
  而不是逐题贴标签：区间天然连续、不重不漏，比逐题判定稳得多。
  结果就是 `言语理解 1-10 / 数字推理 11-20 / …` 这种真实卷面结构（答题卡按它分组）。
- **补全答案**：跑完还有缺答案的题，网页上会出现提示条，点「补全答案」
  或执行 `npm run repair` 单独重跑这些题；补全只补答案，不会改动全卷分类。

调用层（`server/lib/llm.mjs`）统一走**流式** `/chat/completions`：
反代对非流式请求通常有较短的读取空闲超时（本机代理是 90 秒），
推理模型一次思考常常超过这个时间，结果就是 HTTP 200 但内容为空；
流式每收到一个分片就重置空闲计时，长生成不会被误杀。
代理里挂着多把上游密钥时会按"最近使用"排序逐把尝试，
某把被上游掐断就自动换下一把。

### 3. 换成官方答案（可选，但强烈建议）

模型自己做的答案是"推理产物"，会错。如果这份卷子在粉笔上有解析页，
可以直接把**标准答案**导进来覆盖：

```powershell
# 1. 在粉笔解析页（/ti/exam/solution/...）点右上角「下载」，得到解析版 PDF
# 2. 从 PDF 里抽出「正确答案」
python tools/parse_solution_pdf.py "solution.pdf" answers.json

# 3. 合并进题库，并按标准答案重写那几道被改对的题的解析
npm run answers -- <examId> answers.json --reexplain
npm run re-explain -- <examId>        # 想单独重写解析时用
```

导入后题目的 `answerSource` 变成 `fenbi`、置信度 `high`，
界面上会显示"粉笔标准答案"而不是置信度标签。

> 这份样例卷就是这么来的：模型自答 **83.8%**（99 题对 83 题），
> 16 道错题里 11 道是图形推理/空间重构。导入官方答案后全部校正，
> 那 16 道题原有的解析是在为错答案辩护，所以一并按官方答案重写了。

### 4. 导入官方解析（可选，效果最好）

解析版 PDF 里**只有答案没有讲解**，讲解在网页解析页上。那部分数据走的接口
（`combine/static/solution`）要登录态、body 又太大，抓包会被截断，
所以改走"全选复制 → 落盘 → 本地解析"：

```powershell
# 1. 浏览器打开老实卷的解析页，等它把题目都渲染完
#    https://spa.fenbi.com/ti/exam/solution/<key>?routecs=gyqbs&examcatid=1001814
# 2. Ctrl+A 全选、Ctrl+C 复制
# 3. 存到文件并解析（脚本会按「解析」分块，用正确答案校验顺序）
Get-Clipboard -Raw | Set-Content clip.txt -Encoding utf8
python tools/parse_solution_text.py clip.txt <examId>
```

脚本做的事：
- 按「解析」出现顺序切块，逐题取**解析正文 / 考点 / 参考答案**；
- 用「正确答案」字母和题库里已有的答案比对，**不一致超过 15% 直接中止**
  （防止把别的卷子的解析写进来）；
- 论述题（无 ABCD、答案是文字）单独识别成 `kind: essay`，
  存 `answerText` 并把原先混进题干的「✤ 答案…✤ 解析…」剪掉。

导入后 `explanationSource` 变成 `fenbi`，界面上标"粉笔官方解析"，
并显示考点标签。全书 1315 题已全部按此方式补齐。

## 五、API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | Python/PyMuPDF 与模型配置自检 |
| GET/POST | `/api/config` | 读取/保存模型设置（密钥只回掩码） |
| GET | `/api/exams` | 题库列表 |
| POST | `/api/exams` | 上传 PDF（raw body，`Content-Type: application/pdf`） |
| GET | `/api/exams/:id` | 题库全文（含题目、解析、历史成绩） |
| GET | `/api/exams/:id/job` | 解析进度 |
| PATCH | `/api/exams/:id/questions/:no` | 修订答案 / 解析 / 标记 / 笔记 |
| POST | `/api/exams/:id/questions/:no/reanalyze` | 让模型重做这一题（会重算答案） |
| POST | `/api/exams/:id/questions/:no/explain` | 只补解析，不动已验证的答案 |
| POST | `/api/exams/:id/repair` | 补全所有缺答案的题（后台） |
| POST | `/api/exams/:id/reclassify` | 全卷重新分类 |
| POST | `/api/exams/:id/attempts` | 交卷记录一次成绩，并把错题写进错题本。支持 `questionNos`（只统计本次范围）与 `mode: 'sprint'` |
| POST | `/api/exams/:id/suspend` | 中止做题：只判已作答的题，并把作答快照存下来 |
| DELETE | `/api/exams/:id/suspend` | 清掉中断快照（继续做题 / 整卷交卷后） |
| GET | `/api/practice/types` | 按题型刷题的题型总览（题量、覆盖卷数、含图数、已刷数） |
| GET | `/api/practice/questions` | 抽题：`section` + `limit` + `order=fresh|random|seq`（fresh 优先没刷过的） |
| POST | `/api/practice/record` | 按题型练习交回作答：记进度 + 错题进错题本 |
| GET | `/api/practice/session` | 是否有没做完的题型练习（题型页「继续练习」用） |
| POST | `/api/practice/session` | 中止时保存题型练习现场 |
| GET | `/api/practice/session/full` | 取回现场并补上题目内容 |
| DELETE | `/api/practice/session` | 放弃 / 练完后清掉现场 |

## 六、已知边界

- **模型自答的图形题不可靠**：没导官方答案时，视觉模型判读图形推理/空间重构题
  的准确率很低（本卷 20 道图形题里错了 11 道），一律标低置信。
  有解析页的卷子建议走上面的"换成官方答案"流程。
- **解析 PDF 只有答案，没有讲解**：粉笔解析页导出的 PDF 里只有「正确答案 / 你的答案」，
  没有解析文字。所以导入后**解析是空的**，在题目展开后点「生成解析」按需补——
  整套 1300 多题全生成太贵，按需更划算。
- **个别题目可能拿不到答案**：推理模型偶尔会空手而归（思考吃光 token 配额），
  这时题目会保留配图和题干、答案留空，用「补全答案」重跑或手动修订即可。
  另外原卷本身也可能没给答案：2018 那份就有 7 题粉笔也没答案。
- **切题规则偏粉笔版式**：其他来源的 PDF（双栏排版、题号在题干末尾、
  选项用 `A、` 而非 `A.` 等）可能需要调整 `tools/pdf_extract.py` 里的阈值与正则。
- **配图裁白边是尽力而为**：扫描件的阴影、渐变会让自动裁剪失效，
  最坏情况只是图里留白多一点，不会切掉内容（裁切面积超过阈值就跳过）。
- 从零解析一条 99 题的卷子约需 5–10 分钟（取决于模型速度与限流）；
  用 `import-solution.mjs` 导入解析版 PDF 只需 30 秒左右（答案不用模型算）。
